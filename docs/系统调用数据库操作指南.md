# 系统调用数据库操作指南

这份指南按当前代码实际逻辑来写，告诉你怎样一步一步让系统从“数据库分析”按钮读取数据并生成库存预警。

## 1. 先理解当前代码里的“数据库”

页面上的按钮叫：

```text
从数据库分析
```

它提交到：

```text
POST /database-analysis
```

代码位置：

```text
app/routers/upload_router.py
```

调用链路是：

```text
页面点击“从数据库分析”
        ↓
POST /database-analysis
        ↓
build_standard_data_from_database()
        ↓
根据 DB_TYPE 判断走哪个数据源
        ↓
analyze_standard_data()
        ↓
展示预警结果
```

当前 `.env` 是：

```env
DATA_SOURCE=database
DB_TYPE=tplus
```

所以你现在点击“从数据库分析”时，系统不是直连 SQL Server，而是走：

```text
畅捷通 T+Cloud / tplus OpenAPI
```

也就是：

```text
DB_TYPE=tplus 代表从畅捷通接口读数据
```

如果以后你要直连客户 SQL Server，再把 `DB_TYPE` 改成：

```env
DB_TYPE=sqlserver
```

这是另一条路线。

## 2. 当前你应该走哪条路线

你现在正在对接畅捷通自建应用，所以当前路线是：

```text
FastAPI 本地系统
        ↓
cpolar 公网映射
        ↓
畅捷通自建应用消息回调
        ↓
拿 certificate 和 appTicket
        ↓
generateToken 获取 accessToken
        ↓
调用 T+Cloud / tplus OpenAPI
        ↓
生成库存预警
```

因此你现在要先把畅捷通授权链路跑通，再点“从数据库分析”。

## 7. 第五步：填写 .env 基础配置

文件位置：

```text
D:\photo\inventory-warning-system\.env
```

你需要先把这些占位值改掉：

```env
TPLUS_API_BASE_URL=https://openapi.chanjet.com
TPLUS_AUTH_BASE_URL=https://openapi.chanjet.com
TPLUS_AUTH_MODE=self_built
TPLUS_APP_KEY=真实AppKey
TPLUS_APP_SECRET=真实AppSecret
```

当前 `.env` 里还是：

```env
TPLUS_API_BASE_URL=https://api.example.com
TPLUS_APP_KEY=YOUR_APP_KEY
TPLUS_APP_SECRET=YOUR_APP_SECRET
```

这三个必须改。

### 7.1 TPLUS_API_BASE_URL

如果畅捷通业务接口完整地址类似：

```text
https://openapi.chanjet.com/tplus/api/v2/inventory/Query
```

那就填：

```env
TPLUS_API_BASE_URL=https://openapi.chanjet.com
```

### 7.2 TPLUS_APP_KEY

填写畅捷通开放平台自建应用的 AppKey：

```env
TPLUS_APP_KEY=真实AppKey
```

### 7.3 TPLUS_APP_SECRET

填写畅捷通开放平台自建应用的 AppSecret：

```env
TPLUS_APP_SECRET=真实AppSecret
```

### 7.4 TPLUS_AUTH_MODE

保持：

```env
TPLUS_AUTH_MODE=self_built
```

这表示系统用自建应用方式获取 token。

## 8. 第六步：完成管理员授权，拿 certificate

管理员授权成功后，畅捷通会 POST 到：

```text
/tplus/message/callback
```

如果请求 JSON 里包含：

```json
{
  "certificate": "xxxx"
}
```

系统会自动写入 `.env`：

```env
CHANJET_CERTIFICATE=xxxx
```

你需要检查 `.env` 里是否出现：

```env
CHANJET_CERTIFICATE=...
```

代码读取证书时会这样读：

```text
先读 TPLUS_CERTIFICATE
如果为空，再读 CHANJET_CERTIFICATE
```

所以只要 `CHANJET_CERTIFICATE` 有值，系统就能拿它去获取 token。

如果没有自动写入，可以先手动填：

```env
CHANJET_CERTIFICATE=管理员授权得到的certificate
```

## 9. 第七步：等待 appTicket 推送

畅捷通自建应用会定时推送 `appTicket`。

系统收到后会保存到：

```text
outputs/tplus_app_ticket_cache.json
```

你可以检查这个文件是否生成。

如果没有生成，说明还没收到推送。

常见原因：

```text
消息接收地址没填对
消息密钥没填
FastAPI 没启动
cpolar 地址变了
畅捷通还没推送
```

临时测试可以手动在 `.env` 填：

```env
TPLUS_APP_TICKET=t-xxxx
```

注意：`appTicket` 有效期通常只有 30 分钟。

## 10. 第八步：确认 token 获取条件齐了

在点击“从数据库分析”前，至少要有：

```env
TPLUS_AUTH_MODE=self_built
TPLUS_APP_KEY=真实AppKey
TPLUS_APP_SECRET=真实AppSecret
CHANJET_CERTIFICATE=真实certificate
```

还要满足下面两者之一：

```text
outputs/tplus_app_ticket_cache.json 里有未过期 appTicket
```

或者：

```env
TPLUS_APP_TICKET=未过期appTicket
```

否则系统会报：

```text
未找到可用的 appTicket
```

## 12. 如果要直接用 URL 测试

你也可以不用页面按钮，直接发 POST：

```powershell
Invoke-WebRequest -Uri "http://127.0.0.1:8000/database-analysis" -Method Post
```

如果成功，会返回 HTML 结果页。

如果失败，会返回错误页面，错误内容里会显示后端异常。

## 13. 常见错误和处理

### 13.1 请在 .env 中配置真实的 TPLUS_APP_KEY 和 TPLUS_APP_SECRET

说明你还没改：

```env
TPLUS_APP_KEY=YOUR_APP_KEY
TPLUS_APP_SECRET=YOUR_APP_SECRET
```

改成真实值。

### 13.2 请在 .env 配置 TPLUS_CERTIFICATE

当前代码也支持：

```env
CHANJET_CERTIFICATE=xxxx
```

如果这两个都为空，就会报错。

处理：

```text
完成管理员授权
或手动填写 CHANJET_CERTIFICATE
```

### 13.3 未找到可用的 appTicket

说明系统还没收到畅捷通推送，或者缓存过期。

处理：

```text
确认消息接收地址正确
等待畅捷通推送
或者临时手动填写 TPLUS_APP_TICKET
```

### 13.4 业务接口 401 / 403

常见原因：

```text
AppKey/AppSecret 不对
certificate 不对
appTicket 过期
没有申请对应接口权限
TPLUS_API_BASE_URL 不对
```

先检查 `.env`，再检查畅捷通后台权限。

### 13.5 没有数据或结果为空

当前 T+ OpenAPI 代码主要调用：

```text
/tplus/api/v2/inventory/Query
/tplus/api/v2/stock/CurrentStock/Query
```

如果接口返回字段和代码预期字段不一致，需要再按真实返回结构调整字段映射。

## 14. 如果以后要直连客户 SQL Server

这和当前畅捷通 OpenAPI 是另一条路线。

`.env` 要改成：

```env
DB_TYPE=sqlserver
DB_HOST=客户数据库IP
DB_PORT=1433
DB_NAME=数据库名
DB_USER=数据库用户名
DB_PASSWORD=数据库密码
DB_ODBC_DRIVER=ODBC Driver 17 for SQL Server
```

当前 `app/data_sources/database_source.py` 里的 SQL 只是模板：

```text
inventory
sales
hq_inventory
```

到客户现场后，必须根据客户真实表名、字段名、业务口径修改 SQL。

也就是说：

```text
DB_TYPE=tplus
```

走畅捷通 OpenAPI。

```text
DB_TYPE=sqlserver
```

走直连 SQL Server。

这两种不要混在一起。

4. 畅捷通后台填写消息密钥。

5. 畅捷通后台填写消息接收地址：


6. `.env` 填真实值：

```env
TPLUS_API_BASE_URL=https://openapi.chanjet.com
TPLUS_AUTH_MODE=self_built
TPLUS_APP_KEY=真实AppKey

```

7. 完成管理员授权，确认 `.env` 出现：


8. 等待 appTicket 推送，确认生成：


9. 打开系统首页，点击：

```text
从数据库分析
```

10. 如果失败，先看错误页面内容，再按第 13 节排查。
