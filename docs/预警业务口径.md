# 预警业务口径

> 本文档是低库存/缺码预警系统的业务定义，作为代码实现依据。

---

## 1. 四张输入表定义

### 1.1 本地库存表

- **文件名示例**：本地库存表.xlsx
- **表头行**：自动检测（查找含"存货编码"的行）
- **内容**：本地仓库的库存快照
- **关键列**：仓库编码、仓库、存货编码、存货、尺码、现存量(主)、可用量(主)
- **说明**：
  - 仓库列的值即"在途仓"，代表货物所在/发往的仓库
  - 本地库存表虽然包含已发货在途信息，但**当前可用量（可用量(主)）不包含已发货在途**
  - 已发货在途通过"在途仓"字段展示，不参与当前可用量计算
  - 按 006 仓库筛选（`WARNING_WAREHOUSE_CODE`）

### 1.2 近期销售表

- **文件名示例**：近期销售表.xlsx
- **表头行**：自动检测（查找含"存货编码"的行）
- **内容**：近期销售明细
- **关键列**：存货编码、存货、尺码、仓库编码、数量
- **说明**：
  - 用于计算**近7天销量**和**日均销量**
  - 按 006 仓库筛选
  - 只保留数量 > 0 的记录

### 1.3 在途库存表（未发货）

- **文件名示例**：在途库存表.xlsx
- **表头行**：自动检测（查找含"货号/尺码"的行）
- **内容**：未发货的在途库存，**宽表格式**
- **关键列**：货号/尺码（存货编码）+ 各尺码列（100, 110, 120, 130, ...）
- **说明**：
  - 只包含**未发货**在途
  - 不含仓库列（在途仓来自本地库存表）
  - **在途（未发货）暂不参与当前可用量计算，只作为结果展示字段**
  - 需要 melt 为长表格式

### 1.4 总部库存表

- **文件名示例**：苏美达专用-当前可用量二维-0528.xlsx
- **表头行**：第 2 行（index=1）
- **内容**：总部各仓的可用库存，**宽表格式**
- **关键列**：检索号、存货编码、存货名称 + 各尺码列（B90, ZB90, B100, ...）
- **说明**：
  - 只用于计算**总部可调数量**
  - 存货编码取后 11 位匹配
  - 需要 melt 为长表格式

## 2. 标准数据字段定义

四表合一 + T+ API 查询后，输出 13 列标准 DataFrame：

| # | 字段名 | 类型 | 说明 |
|---|--------|------|------|
| 1 | 存货编码 | str | SKU 唯一标识 |
| 2 | 存货 | str | 商品名称 |
| 3 | 尺码 | str | 尺码（清洗后） |
| 4 | 近7天销量 | float | 近 7 天销售数量合计（006 仓库） |
| 5 | 日均销量 | float | 近7天销量 / 7 |
| 6 | 近90天销量 | float | 近 90 天销售数量合计（来自 T+ API） |
| 7 | 仓库编码 | str | 本地仓库编码（006） |
| 8 | 仓库 | str | 本地仓库名称 |
| 9 | 当前现存量 | float | 本地现存量合计 |
| 10 | 当前可用量 | float | 本地可用量合计 |
| 11 | 总部库存 | float | 总部可调库存合计 |
| 12 | 在途仓 | str | 在途货物所在仓库名（来自本地库存表的仓库列） |
| 13 | 在途（未发货） | float | 未发货在途数量合计（来自在途库存表） |

## 3. 字段来源

| 字段名 | 来源表/接口 | 计算方式 |
|--------|------------|----------|
| 存货编码 | 本地库存表 / 近期销售表 / 在途库存表 | 各表清洗后按编码合并 |
| 存货 | 本地库存表 | 直接取值，缺失时从销售表补全 |
| 尺码 | 各表 | 清洗（去"码"字、去浮点尾缀） |
| 近7天销量 | 近期销售表 | 按 存货编码+尺码 聚合 sum(数量)，筛选 006 仓库 |
| 日均销量 | 计算 | 近7天销量 / 7 |
| 近90天销量 | **T+ API** | `query_90day_sales()` 实时查询，不来自上传表 |
| 仓库编码 | 本地库存表 | 聚合时取 first |
| 仓库 | 本地库存表 | 聚合时取 first |
| 当前现存量 | 本地库存表 | 按 存货编码+尺码 聚合 sum(现存量) |
| 当前可用量 | 本地库存表 | 按 存货编码+尺码 聚合 sum(可用量) |
| 总部库存 | 总部库存表 | 按 存货编码+尺码 聚合 sum(可用量)，无数据时为 0 |
| 在途仓 | 本地库存表 | 仓库列的值，聚合时取 first |
| 在途（未发货） | 在途库存表 | 按 存货编码+尺码 聚合 sum(各尺码数量)，无数据时为 0 |

**合并顺序**：
1. 销售 LEFT JOIN 库存（按 存货编码+尺码）
2. 合并总部库存（LEFT JOIN）
3. 合并近90天销量（LEFT JOIN）
4. 合并在途未发货（LEFT JOIN）

## 4. 预警规则

### 4.1 预警状态判断（按优先级从高到低）

> **重要**：红色/黄色预警和调货建议基于"当前可用量"计算。当前可用量**不包含**已发货在途和未发货在途。

| 优先级 | 预警状态 | 判断条件 |
|--------|---------|----------|
| 1 | **红色预警** | 当前可用量 ≤ 0 **且** 近7天销量 > 0 |
| 2 | **橙色缺码** | 当前现存量 ≤ 0 **且** 近90天销量 > 0（且不满足红色） |
| 3 | **黄色预警** | 当前可用量 > 0 **且** 近7天销量 > 0 **且** 可售天数 < 7 |
| 4 | **正常** | 以上均不满足 |

### 4.2 关键区别

- **红色 vs 橙色**：红色要求"近7天有销量"，橙色只要求"近90天有销量"
  - 红色 = 近期有需求但完全没可用库存
  - 橙色 = 近期无需求但历史有销售，本地无现货
- **当前可用量 vs 当前现存量**：
  - 可用量 = 现存量 - 已分配/锁定
  - 红色看可用量（能不能卖），橙色看现存量（有没有货）

## 5. 调货计算规则

> **重要**：调货建议基于"当前可用量"计算。当前可用量**不包含**已发货在途和未发货在途。

| 指标 | 公式 | 说明 |
|------|------|------|
| 可售天数 | 当前可用量 / 日均销量 | 无销量时为 999（显示用） |
| 目标库存 | 日均销量 × 7 | 7 天安全库存 |
| 建议调货量 | max(目标库存 - 当前可用量, 0) | 向上取整 |
| 总部可调数量 | min(总部库存, 建议调货量) | 总部最多能调多少 |
| 剩余缺口 | 建议调货量 - 总部可调数量 | 总部也调不够时的差额 |

### 调货建议文案

| 预警状态 | 文案前缀 | 示例 |
|---------|---------|------|
| 红色预警 | 建议立即调货 | "建议立即调货 10 件；总部可满足" |
| 橙色缺码 | 缺码待补 | "缺码待补 5 件；总部暂无可调库存" |
| 黄色预警 | 建议尽快调货 | "建议尽快调货 3 件；总部可调 2 件，仍缺 1 件" |
| 正常 | - | "-" |

## 6. T+ API 依赖

### 6.1 近90天销量

- **必须从 T+ API 实时获取**，不来自上传 Excel
- 调用方式：`query_90day_sales()` → `TPlusOpenAPIClient().query_recent_sale_delivery_sales(days=90)`
- 返回列：`存货编码, 尺码, 近90天销量`（不含日均销量，避免与近7天日均混淆）

### 6.2 Excel 分析模式下 T+ 失败处理

Excel 四表分析时，系统会尝试连接 T+ API 读取近90天销量。

**T+ 成功时**：
- 正常计算红色、橙色、黄色、绿色预警。

**T+ 失败时**：
- **不中断**整个 Excel 分析。
- 近90天销量按 **0** 处理。
- 本次**不计算橙色缺码预警**。
- 仍然继续计算红色、黄色、绿色预警。
- 页面必须提示用户：

  > "T+ 近90天销量获取失败，本次未计算橙色缺码预警，仅完成红黄绿库存预警。"

**T+ 失败包括以下情况**：
- 配置缺失（未配置 TPLUS_API_BASE_URL 等）
- 未授权或 token 过期
- 网络不通
- 接口超时
- 接口权限不足
- T+ 返回异常数据

**后续演进**：
- 可增加配置开关，允许用户选择"失败即终止"或"降级分析"
- 本轮默认**降级分析**

### 6.3 T+ 直接分析模式

- 本地库存、近7天销售、近90天销售均来自 T+ API
- 在途未发货和总部库存来自上传 Excel
- 上传 2 个文件：在途库存表、总部库存表
