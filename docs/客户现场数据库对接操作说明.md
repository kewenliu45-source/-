# 客户现场数据库对接操作说明

## 1. 目的

当前系统已经可以通过上传 Excel 表格完成库存预警分析。后续到客户公司后，需要通过 VPN 连接客户内网，并从客户公司的数据库直接读取库存、销售、总部库存等业务数据。

本文档用于说明：

- 到客户现场前需要准备什么。
- 到客户现场后怎么连接和测试。
- 是否需要安装 SQL 或数据库软件。
- 现场需要客户提供哪些数据库信息。

## 2. 现场前准备

### 2.1 本地系统准备

到客户现场前，建议先确认本机可以正常运行现有系统：

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

浏览器访问：

```text
http://127.0.0.1:8000
```

先用本地 Excel 样表跑通一次，确认页面、分析结果、预警逻辑正常。

### 2.2 需要提前确认的客户信息

请客户提前提供以下信息：

| 信息 | 说明 |
| --- | --- |
| VPN 客户端 | 客户使用的 VPN 软件名称和安装包 |
| VPN 账号 | 登录 VPN 的账号、密码、动态验证码方式 |
| 数据库类型 | SQL Server、MySQL、PostgreSQL、Oracle 等 |
| 数据库地址 | 内网 IP 或域名 |
| 数据库端口 | 例如 SQL Server 常见 1433，MySQL 常见 3306 |
| 数据库名称 | 需要连接的业务库名称 |
| 数据库账号 | 建议提供只读账号 |
| 数据库密码 | 对应账号密码 |
| 表名 | 库存表、销售表、总部库存表等真实表名 |
| 字段说明 | 商品编码、商品名称、尺码、仓库、现存量、可用量、销售数量、业务日期等字段 |
| 数据口径 | 近 7 天销售按哪个日期字段算，库存用现存量还是可用量 |

建议客户提供一个只读账号，不需要写入、删除、修改权限。

## 3. 是否需要安装 SQL

一般不需要在你的电脑上安装完整的数据库服务。

你不需要安装一套 SQL Server、MySQL 或 Oracle 数据库服务器，因为数据库已经在客户公司的内网服务器上。你的电脑只需要能通过 VPN 访问它。

实际可能需要安装的是以下两类东西：

### 3.1 数据库客户端工具，建议安装但不是必须

数据库客户端工具用于现场排查连接和查看表结构，例如：

| 数据库类型 | 推荐工具 |
| --- | --- |
| SQL Server | SQL Server Management Studio 或 Azure Data Studio |
| MySQL | DBeaver、Navicat、MySQL Workbench |
| PostgreSQL | DBeaver、pgAdmin |
| Oracle | DBeaver、Oracle SQL Developer |

这些工具不是系统运行的必需品，但现场调试很有用。建议安装 DBeaver，因为它支持多种数据库。

### 3.2 Python 数据库驱动，系统连接数据库时需要

系统真正运行时，需要安装对应数据库的 Python 驱动。具体装哪个，取决于客户数据库类型：

| 数据库类型 | 常见 Python 依赖 |
| --- | --- |
| SQL Server | `sqlalchemy` + `pyodbc` |
| MySQL | `sqlalchemy` + `pymysql` |
| PostgreSQL | `sqlalchemy` + `psycopg2-binary` |
| Oracle | `sqlalchemy` + `oracledb` |

如果客户是 SQL Server，通常还需要安装 Microsoft ODBC Driver for SQL Server。

结论：

- 不需要安装完整数据库服务器。
- 建议安装一个数据库客户端工具，方便现场查表和跑 SQL。
- 系统需要安装对应数据库的 Python 驱动。
- 如果是 SQL Server，通常还需要安装 ODBC 驱动。

## 4. 客户现场操作步骤

### 4.1 连接 VPN

1. 打开客户提供的 VPN 客户端。
2. 输入 VPN 账号、密码和验证码。
3. 连接成功后，确认可以访问客户内网。

可以用以下方式初步检查网络是否通：

```bash
ping 数据库内网地址
```

如果客户禁用了 ping，不代表数据库一定不通，需要继续测试数据库端口。

### 4.2 测试数据库端口

在 PowerShell 中执行：

```powershell
Test-NetConnection 数据库内网地址 -Port 数据库端口
```

例如 SQL Server：

```powershell
Test-NetConnection 192.168.1.10 -Port 1433
```

如果 `TcpTestSucceeded` 为 `True`，说明网络和端口基本可达。

本项目当前客户 SQL Server 2008 R2 的连接信息已经准备在 `.env` 中：

```text
DB_TYPE=sqlserver
DB_HOST=192.168.0.9
DB_PORT=1433
DB_NAME=UFTData541042_000003
DB_USER=tplus
DB_ODBC_DRIVER=SQL Server
```

连上客户 VPN 后，可以在项目目录执行下面的命令，只测试数据库登录和 `SELECT 1`，不会读取业务表：

```bash
python scripts/test_db_connection.py
```

如果输出 `数据库连接成功`，说明账号、密码、数据库名、驱动和网络都基本可用。

### 4.3 使用数据库客户端确认连接

打开 DBeaver、SSMS 或其他数据库客户端，输入：

- 数据库类型
- 地址
- 端口
- 数据库名称
- 用户名
- 密码

连接成功后，确认能看到目标数据库和业务表。

### 4.4 确认业务表和字段

需要重点确认以下数据来源：

#### 本地门店库存

必须能得到：

- 商品编码
- 商品名称
- 尺码
- 仓库编码
- 仓库名称
- 当前现存量
- 当前可用量

#### 近期销售

必须能得到：

- 商品编码
- 商品名称
- 尺码
- 销售数量
- 销售日期或出库日期

系统默认按近 7 天销售计算日均销量，现场需要确认客户是否认可这个口径。

#### 总部库存

必须能得到：

- 商品编码
- 尺码
- 总部可调拨库存

如果客户总部库存是横向尺码表，需要在系统中转换成长表后再分析。

### 4.5 配置系统数据库连接

正式改造后，建议通过环境变量或 `.env` 配置数据库连接，不把账号密码写进代码。

示例：

```text
DATA_SOURCE=database
DB_TYPE=sqlserver
DB_HOST=192.168.1.10
DB_PORT=1433
DB_NAME=customer_db
DB_USER=readonly_user
DB_PASSWORD=your_password
```

如果还没有切换到数据库模式，可以继续使用 Excel 上传模式测试系统分析逻辑。

### 4.6 启动系统

在项目目录执行：

```bash
uvicorn app.main:app --reload
```

浏览器访问：

```text
http://127.0.0.1:8000
```

如果已经开发数据库读取入口，点击“从数据库分析”或对应按钮，系统会自动读取客户数据库并生成预警结果。

## 5. 现场验证清单

现场联调时，按以下顺序验证：

1. VPN 是否连接成功。
2. 数据库地址和端口是否可达。
3. 数据库账号是否能登录。
4. 账号是否有目标表的查询权限。
5. 库存表是否能查到数据。
6. 销售表是否能按日期查到近 7 天数据。
7. 商品编码和尺码格式是否和 Excel 版本一致。
8. 可用量、现存量、总部库存字段是否口径正确。
9. 系统生成的红色、黄色、正常预警数量是否合理。
10. 抽查几个 SKU，和客户人工计算结果对比。

## 6. 常见问题

### 6.1 VPN 连上了，但数据库连不上

可能原因：

- 数据库服务器 IP 或端口不正确。
- VPN 账号没有访问数据库网段的权限。
- 数据库服务器防火墙限制了访问来源。
- 数据库只允许指定应用服务器访问。

需要客户 IT 协助确认网络权限。

### 6.2 数据库客户端能连，系统不能连

可能原因：

- Python 数据库驱动没有安装。
- SQL Server 缺少 ODBC Driver。
- 数据库连接字符串配置错误。
- 密码中有特殊字符，连接字符串没有正确转义。

### 6.3 查询很慢

可能原因：

- 销售明细表数据量太大。
- 查询没有限制日期范围。
- 相关字段没有索引。
- SQL 中做了过多实时聚合。

建议先只查询近 7 天销售数据，并让客户 DBA 确认索引。

### 6.4 预警结果和 Excel 版本不一致

重点检查：

- 商品编码是否被自动转成数字或带 `.0`。
- 尺码是否有空格、中文前缀或大小写差异。
- 销售数量是否包含退货或负数。
- 库存使用的是现存量还是可用量。
- 总部库存是否只统计可调拨库存。

## 7. 建议现场携带的软件

建议提前准备：

- Python 环境。
- 当前项目代码。
- 项目依赖包。
- DBeaver 或客户指定数据库客户端。
- VPN 客户端安装包。
- 如果客户是 SQL Server，准备 Microsoft ODBC Driver for SQL Server。
- 可离线安装的 Python 数据库驱动包，防止客户现场不能访问外网。

## 8. 推荐现场沟通问题

到客户现场后，建议先问清楚：

1. 库存预警以哪个仓库为分析对象？
2. “当前可用量”是否已经扣除了锁定库存、在途、已分配数量？
3. 销售数据是否包含退货、换货、取消订单？
4. 近 7 天销售是否按自然日、营业日还是最近 7 个有销售日？
5. 总部库存中哪些仓库可以调拨，哪些不能调拨？
6. 数据每天什么时候更新？
7. 是否需要定时自动生成预警，而不是人工点击分析？

## 9. 总结

到客户现场前，系统可以继续用 Excel 上传模式开发和验证。

到客户现场后，主要工作不是重写预警算法，而是确认客户数据库连接、真实表结构、字段口径和 SQL 查询结果。数据库对接完成后，系统应保持同一套预警分析逻辑，只把数据来源从 Excel 切换为客户数据库。
