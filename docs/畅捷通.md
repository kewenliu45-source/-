# 畅捷通对接操作文档

本文档对应当前 FastAPI 项目的最新代码状态，说明畅捷通自建应用如何配置、系统接口如何工作、以及你需要手动填写哪些内容。

## 1. 当前对接模式

当前系统使用：

```text
畅捷通自建应用模式
```

不是应用入驻 OAuth 授权码模式。

当前 token 流程：

```text
管理员授权回调返回 certificate
        ↓
系统保存 certificate 到 .env
        ↓
畅捷通消息订阅推送 appTicket
        ↓
系统保存 appTicket
        ↓
系统用 appTicket + certificate 获取 accessToken
        ↓
调用 T+Cloud / tplus 业务接口
```

自建应用获取 token 接口：

```text
https://openapi.chanjet.com/v1/common/auth/selfBuiltApp/generateToken
```

### 2.2 消息接收地址

畅捷通后台的消息接收地址填写：

```text
https://66f17b6b.r28.cpolar.top/tplus/message/callback
```

这个接口用于：

```text
接收管理员授权回调
接收 certificate
接收消息订阅推送

```

### 2.3 消息密钥
1234567812345678

如果后台提示：

```text
正式环境没有秘钥，请先填写秘钥
```

你需要先在畅捷通后台的消息订阅或消息配置页面填写“消息密钥”。

消息密钥不是：

```text
AppSecret
certificate
```

它是消息推送验签用的密钥。

畅捷通会使用消息密钥对消息正文进行 AES-ECB 加密，并通过 `encryptMsg` 字段推送。系统会读取
`.env` 中的 `CHANJET_MESSAGE_SECRET` 解密消息，再提取 `appTicket`。

### 2.4 管理员授权

管理员授权后，畅捷通会向消息接收地址 POST JSON。

如果请求里包含：

```json
{
  "certificate": "xxxx"
}
```

系统会自动写入 `.env`：

```env
CHANJET_CERTIFICATE=xxxx
```

## 3. 当前系统接口说明

### 3.1 POST /tplus/message/callback

代码位置：

```text
app/routers/tplus_oauth_router.py
```

作用：

```text
接收畅捷通 POST 的 JSON 数据
打印完整请求内容
如果包含 certificate，保存到 .env
如果包含 appTicket，保存到 appTicket 缓存文件
返回成功
```

返回值：

```json
{
  "result": "success",
  "code": 0,
  "msg": "success"
}
```

保留 `result: "success"` 是为了兼容畅捷通后台的消息地址验证。

核心逻辑：

```python
@router.api_route("/tplus/message/callback", methods=["GET", "POST"])
async def tplus_message_callback(request: Request):
    payload = dict(request.query_params)
    body = {}

    if request.method == "POST":
        try:
            body = await request.json()
        except Exception:
            body = {}

        if isinstance(body, dict):
            payload.update(body)

    print("收到畅捷通消息回调：")
    print({
        "method": request.method,
        "url": str(request.url),
        "headers": dict(request.headers),
        "query_params": dict(request.query_params),
        "body": body,
        "merged_payload": payload,
    })

    certificate = payload.get("certificate")
    if certificate:
        save_chanjet_certificate(str(certificate))

    app_ticket = _extract_app_ticket(payload)
    if app_ticket:
        TPlusOpenAPIClient().save_app_ticket(payload)

    return {
        "result": "success",
        "code": 0,
        "msg": "success",
    }
```

## 4. .env 需要手动填写什么

文件位置：

```text
D:\photo\inventory-warning-system\.env
```

你需要重点检查这些配置：

```env
DATA_SOURCE=database
DB_TYPE=tplus

TPLUS_API_BASE_URL=https://openapi.chanjet.com
TPLUS_AUTH_BASE_URL=https://openapi.chanjet.com
TPLUS_AUTH_MODE=self_built

TPLUS_APP_KEY=真实AppKey
TPLUS_APP_SECRET=真实AppSecret
CHANJET_MESSAGE_SECRET=后台配置的消息密钥

TPLUS_CERTIFICATE=
CHANJET_CERTIFICATE=

TPLUS_APP_TICKET=
TPLUS_APP_TICKET_MAX_AGE_SECONDS=1500

TPLUS_REQUEST_TIMEOUT=20
TPLUS_RETRY_TIMES=3
TPLUS_QUERY_PAGE_SIZE=200
```

### 4.1 TPLUS_API_BASE_URL

业务接口基础地址。

如果你的业务接口是：

```text
https://openapi.chanjet.com/tplus/api/v2/inventory/Query
```

则填写：

```env
TPLUS_API_BASE_URL=https://openapi.chanjet.com
```

如果畅捷通给你的业务域名不是这个，以实际接口文档为准。

### 4.2 TPLUS_AUTH_BASE_URL

认证接口基础地址：

```env
TPLUS_AUTH_BASE_URL=https://openapi.chanjet.com
```

### 4.3 TPLUS_AUTH_MODE

必须填写：

```env
TPLUS_AUTH_MODE=self_built
```

表示当前使用自建应用模式。

### 4.4 TPLUS_APP_KEY

填写畅捷通开放平台 AppKey：

```env
TPLUS_APP_KEY=真实AppKey
```

不能保留：

```env
TPLUS_APP_KEY=YOUR_APP_KEY
```

### 4.5 TPLUS_APP_SECRET

填写畅捷通开放平台 AppSecret：

```env
TPLUS_APP_SECRET=真实AppSecret
```

不能保留：

```env
TPLUS_APP_SECRET=YOUR_APP_SECRET
```

### 4.6 CHANJET_CERTIFICATE

管理员授权回调后，系统会自动写入：

```env
CHANJET_CERTIFICATE=xxxx
```

代码读取证书时会优先读：

```env
TPLUS_CERTIFICATE
```

如果为空，再读：

```env
CHANJET_CERTIFICATE
```

所以你可以不用手动填 `TPLUS_CERTIFICATE`，只要管理员授权回调成功，系统会自动保存 `CHANJET_CERTIFICATE`。

### 4.7 TPLUS_APP_TICKET

通常留空：

```env
TPLUS_APP_TICKET=
```

正常情况下，畅捷通会把 `appTicket` 推送到：

```text
/tplus/message/callback
```

系统会保存到：

```text
outputs/tplus_app_ticket_cache.json
```

临时测试时，也可以手动填一个未过期的 appTicket：

```env
TPLUS_APP_TICKET=t-xxxx
```

appTicket 有效期通常是 30 分钟。

### 4.8 TPLUS_APP_TICKET_MAX_AGE_SECONDS

当前配置：

```env
TPLUS_APP_TICKET_MAX_AGE_SECONDS=1500
```

表示系统只使用 25 分钟内收到的 appTicket。

## 5. token 获取逻辑讲解

代码位置：

```text
app/data_sources/tplus_openapi_source.py
```

核心方法：

```python
get_access_token()
```

逻辑：

```text
1. 先读 outputs/tplus_token_cache.json
2. 如果 access_token 没过期，直接返回
3. 如果过期，判断 TPLUS_AUTH_MODE
4. 如果是 self_built：
   - 读取 certificate
   - 读取 appTicket
   - 调 generateToken
   - 保存新 token
5. 返回 access_token
```

自建应用 token 请求：

```json
{
  "appTicket": "t-xxxx",
  "certificate": "xxxx"
}
```

请求头：

```text
appKey: 你的 AppKey
appSecret: 你的 AppSecret
Content-Type: application/json
```

响应里的字段可能是 camelCase：

```json
{
  "result": true,
  "value": {
    "accessToken": "...",
    "refreshToken": "...",
    "expiresIn": 518400,
    "refreshExpiresIn": 2512799,
    "userId": "...",
    "orgId": "...",
    "appName": "...",
    "scope": "auth_all"
  }
}
```

代码会统一转成内部字段：

```json
{
  "access_token": "...",
  "refresh_token": "...",
  "access_token_expires_at": 1234567890,
  "refresh_token_expires_at": 1234567890,
  "user_id": "...",
  "org_id": "...",
  "app_name": "...",
  "scope": "auth_all"
}
```

业务接口请求头使用：

```text
openToken: access_token
```

如果 token 缓存里有 `sid`，还会带：

```text
Cookie: sid=xxx
```

## 8. 常见报错

### 8.1 正式环境没有秘钥，请先填写秘钥

原因：

```text
畅捷通后台消息订阅没有填写消息密钥
```

处理：

```text
先在畅捷通后台填写消息密钥
再填写消息接收地址
```

### 8.2 消息地址响应状态码非 200

原因：

```text
FastAPI 没启动
cpolar 没启动
cpolar 地址变了
接口返回了错误状态码
```

当前代码已经让 `/tplus/message/callback` 返回 200。

### 8.3 消息地址响应值 result 非 success

原因：

```text
畅捷通要求响应里有 result=success
```

当前代码已经返回：

```json
{
  "result": "success",
  "code": 0,
  "msg": "success"
}
```

### 8.4 没有收到 certificate

检查：

```text
管理员授权是否完成
授权回调地址是否填写 /tplus/message/callback
FastAPI 是否启动
cpolar 是否可访问
```

收到后 `.env` 应该出现：

```env
CHANJET_CERTIFICATE=xxxx
```

### 8.5 未找到 appTicket

检查：

```text
消息订阅是否开启
消息接收地址是否正确
畅捷通是否已经推送 appTicket
outputs/tplus_app_ticket_cache.json 是否生成
```

临时测试可以手动填写：

```env
TPLUS_APP_TICKET=t-xxxx
```
